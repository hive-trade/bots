# Kalshi example

Use the [root setup guide](../../README.md) and clone the entire repository.
This entry point uses the shared runner with `VENUE=kalshi`; it contains no
HiveTrade production strategy or automatic market selection.

From the repository root:

```bash
npm ci
npm run setup   # you run this yourself, in your own terminal
npm run check
npm test
node --env-file=.env examples/kalshi-bot-starter/bot.mjs
```

Before the final command, register the public signing address as a Kalshi bot
Hive (the root README's step 2: a pre-filled link you open and confirm). Set its Hive ID, an exact open supported ticker and
your example side/price cap (`npm run settings -- KALSHI_TICKER=...`; your agent never opens `.env`). Keep live trading false. The adjacent `.env.example`
is a reference: do not copy it over the signing key generated by setup.

Connect your eligible, funded Kalshi account's API key in HiveTrade Settings
and complete execution consent. Only the platform signing key belongs
in the runner. HiveTrade executes the signed v2 intent using the connected
account; the example does not hold an RSA key, submit a second venue order or
report a Polymarket-style fill.

The dry run reads public market data, checks once and exits. It is not a demo
exchange and does not place orders. Only markets in the series listed at
https://docs.hivetrade.com/run-a-bot/kalshi pass the bot API gate (set
`KALSHI_TICKER`, or `KALSHI_SERIES` for the market of a series open right now). The generic price-limit example is not
a forecast; implement your own idea in root `strategy.mjs`.

Keep the journal on persistent storage. See [recovery](../../docs/recovery.md)
for any uncertain response; never delete state to force another order.
